# Grammar Basics

## Rules And Start Symbols

Rules are written as non-terminals on the left and productions on the right.

```text
S ::= Greeting Target;
Greeting ::= "Hello" | "Welcome";
Target ::= traveler | world;
```

Each declaration ends with `;`.

By default, Polygen generates from the non-terminal `S`.

If your grammar uses a different entry symbol, pass `start` when generating:

```ts
import { polygen } from "polygen";

const grammar = `
Greeting ::= "Hello" | "Welcome";
Target ::= traveler | world;
Entry ::= Greeting Target;
`;

const text = polygen(grammar, { start: "Entry" });
```

## Terminals and Non-Terminals

- Quoted text like `"Hello"` is emitted literally.
- Bare lowercase words like `traveler` are also terminals.
- Bare uppercase identifiers like `Greeting` are non-terminals.

That means a capitalized output word such as `"Pet"` must be quoted if you want literal text instead of a non-terminal reference.

```text
S ::= a Pet called "Pet";
Pet ::= cat | dog;
```

Quoted terminals are also how you emit punctuation or syntax characters literally:

```text
S ::= "(" (apple | orange) ")";
```

The historical OCaml lexer was mostly ASCII-oriented. The TypeScript port intentionally broadens this so valid grammars can contain Unicode text without caller-side cleanup.

- Unicode bare terminals are supported.
- Unicode quoted terminals are supported.
- Unicode non-terminals are supported when they begin with an uppercase or titlecase character according to the current tokenizer rules.

## Quoting Rules

Use quotes when you need literal text that would otherwise be interpreted as grammar syntax or a different token kind.

Common cases:

- words beginning with a capital letter
- punctuation such as `(` or `)`
- characters that are part of Polygen syntax
- reserved words when you want them emitted as text

```text
S ::= "(" Hello ")" | "import" | "As Written";
Hello ::= world;
```

See the API and troubleshooting pages for current error behavior around malformed quote escapes.

## Subproductions

Round brackets create a grouped subproduction inside a larger sequence.

```text
S ::= an (apple | orange) is on the (table | desk);
```

This behaves like an inline grammar block. Each parenthesized group makes its own choice when generation reaches it.

Grouping is also important for probability shaping. These two grammars do not have the same distribution:

```text
S1 ::= cat | cow | camel;
S2 ::= cat | (cow | camel);
```

`S1` gives each output a one-in-three chance. `S2` gives `cat` a one-in-two chance, then chooses between `cow` and `camel` only if the grouped branch was selected.

## Optional Subproductions

Square brackets create an optional subproduction.

```text
S ::= an apple [on the table];
```

In the current Polygen language, `[ ... ]` is equivalent to a grouped subproduction that can either produce its body or epsilon. That means it behaves like a 50% choice between:

- producing the body once
- producing nothing

```text
S ::= [ball];
```

This is effectively the same idea as:

```text
S ::= ball | _;
```

## Comments

Polygen supports OCaml-style comments.

```text
S ::= apple | orange (* | banana *) | mango;
(* this whole line is ignored *)
```

Comments are ignored by the tokenizer and do not affect generation.

The current TypeScript tokenizer also supports nested comments, matching the historical behavior.

## Useful Operators

This page covers the basic grammar surface. The operator guide covers deeper behavior and edge cases.

| Syntax | Meaning                                              |
| ------ | ---------------------------------------------------- |
| `\|`   | Alternative                                          |
| `_`    | Epsilon, meaning no output                           |
| `^`    | Concatenate with no space                            |
| `\`    | Capitalize the next terminal output                  |
| `[X]`  | Optional group                                       |
| `{X}`  | Mobile group that can permute position               |
| `>X`   | Unfold target at compile time into a subgrammar form |
| `<X`   | Lock a target against unfolding                      |

See [Operators](/docs/guides/operators) for detailed examples and caveats.

## Labels

Labels let you filter alternatives.

```text
S ::= Greeting;
Greeting ::= formal: "Good day" | casual: "Hi" | "Hello";
```

Generation with `labels: ["formal"]` keeps the `formal` branch and still allows unlabeled branches.

See [Labels and Scoping](/docs/guides/labels-scoping) for more detail on explicit selection, multiselect, and nested declarations.

## Assign vs Define

```text
S ::= X X;
X := one | two;
```

`:=` memoizes the chosen value within a generation run, so both `X` expansions match. Use `::=` when you want each expansion to be chosen independently.

## Segments

If you only have a production body such as `alpha | beta | gamma`, use `polygenSegment(...)` instead of manually wrapping it into a full grammar string.
