# Labels and Scoping

## Labeled Alternatives

Labels attach metadata to a sequence.

```text
S ::= Greeting;
Greeting ::= formal: "Good day" | casual: "Hi" | "Hello";
```

At generation time, labels act as a filter over alternatives.

An alternative is eligible when it is:

- unlabeled, or
- labeled with one of the active labels

## Active Label Environments

```ts
import { polygen } from "polygen";

const text = polygen(grammar, {
  labels: ["formal"]
});
```

This matches the current legacy-compatible behavior of the port.

## Explicit Label Selection

```text
S ::= Greeting.formal;
Greeting ::= formal: "Good day" | "Hello";
```

Explicit selection activates a label for the selected target.

More precisely, the selected label is added to the active label set while generating the target to the left of the dot.

That means selections propagate downward through the generation of the selected target.

```text
S ::= Verb.ing;
Verb ::= (inf: to) (eat | drink | jump) (ing: ^ing);
```

This allows the selected target to keep all unlabeled pieces and only the pieces labeled `ing`.

If the label is not available on the target and the compiler can determine that statically, compilation fails with `CompileError`.

If you opt into `compilePolicy: { preset: "compat" }`, the compiler can instead ignore invalid explicit label selections with a warning.

## Multi-Selection

```text
S ::= Greeting.(formal|casual);
```

Multi-selection chooses one of the provided labels at generation time and activates it for the selected target.

This is the compact way to express several selection paths without manually repeating the whole selected expression.

### Weighted Multi-Selection

Multi-selection labels accept the same weighting modifiers as ordinary production alternatives.

```text
S ::= Greeting.(+formal|--casual|plain);
```

The current implementation uses the same relative weighting rule here as it does for productions. Labels with more positive weight are chosen more often than labels with more negative weight.

## Selection Reset

A bare dot with no label resets the active label set for the selected target.

```text
S ::= Digit | S.nz [^ S.];
Digit ::= z: 0 | nz: >(1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9);
```

`S.nz` activates `nz` while descending into that target. `S.` then clears the active labels for the nested occurrence.

This matters because label selection is additive by default. Reset is the escape hatch when a label should stop propagating.

## Destructive Selection Caveat

Selections can also silently remove too much if the chosen label does not match any labeled branches inside a sequence you expected to survive.

```text
S ::= a A.z;
A ::= x: x | y: y;
```

This can collapse the selected target to nothing and leave just `a`.

The historical OCaml project had a dedicated destructive-selection warning for this class of problem. The current TypeScript package does not emit that warning yet, so this is worth checking manually when heavily label-driven grammars behave oddly.

## Bindings

Polygen has two binding modes.

### Weak Binding / Closure: `::=`

`::=` defines a normal non-terminal. Each time that symbol is generated, the production is evaluated again in the environment where it was defined.

```text
S ::= Fruit and Fruit;
Fruit ::= an apple | a mango | an orange;
```

The two `Fruit` occurrences are independent.

### Strong Binding / Suspension / Assignment: `:=`

`:=` memoizes the generated value for the rest of the current generation run.

```text
S ::= Fruit and Fruit;
Fruit := an apple | a mango | an orange;
```

Now both `Fruit` occurrences agree.

This is why the docs often describe `:=` as memoized assignment.

The first expansion still generates from the symbol's own production in its defining environment. That is what lets recursive strong bindings remain meaningful instead of being replaced by a literal stored string too early.

## Top-Level Environment

Top-level declarations live in one mutually recursive environment.

```text
S ::= S | A | B | s;
A ::= S | A | B | a;
B := S | A | B | b;
```

Any top-level declaration can refer to the other top-level declarations, whether they appear earlier or later in the source.

## Local Bindings In Groups

Groups can introduce local declarations before their main body.

```text
S ::= (X := Adj; Very ::= very [Very]; X ^ "," maybe Very X | definitely Very Adj) and Adj;
Adj ::= handsome | nice;
```

Inside that grouped subgrammar, `X` and `Very` are local names. Outside it, only `Adj` remains visible.

## Nested Scopes

Grouped subgrammars can declare local symbols.

```text
S ::= (S ::= "inner"; >S) | "outer";
```

Nested scopes may shadow outer declarations. The compiler rejects duplicate declarations only within the same scope.

Shadowing is lexical: an inner declaration hides an outer declaration with the same name while generation remains inside that inner scope.

## Static Lexical Scoping

Productions are generated in the environment where they were defined, not in whatever environment happens to call them later.

```text
S ::= (X ::= a | b; A);
A ::= X X;
X := x | y;
```

`A` still sees the top-level `X`, because `A` was defined in the top-level environment.

That is the core closure behavior behind lexical scoping in Polygen.

## Assignment Scope

Assignments memoize within a single generation run and within the environment where that binding lives.

```text
S ::= X X;
X := one | two;
```

Assignment bindings memoize within a single generation run. They are useful when several expansions must agree on one generated value.
