# Operators Reference

## Alternation: `|`

Use `|` to choose between alternatives in a production.

```text
S ::= red | blue | green;
```

Alternation chooses one production from the current series.

When all alternatives are unmodified, each one gets the same share of the probability for that series.

## Production Weighting: `+` and `-`

Prefix `+` and `-` operators change how likely a production is relative to the other productions in the same alternation series.

```text
S ::= +an apple | -an orange | some meat | --a lemon;
```

The current TypeScript parser implements the same weighting model used by the historical language: each production is expanded relative to the lowest modifier in the same series.

In the example above, the effective counts are:

- `+an apple` -> 4 shares
- `-an orange` -> 2 shares
- `some meat` -> 3 shares
- `--a lemon` -> 1 share

That means `an apple` is most likely and `a lemon` is least likely.

The same weighting rule is also used inside multi-selection label lists such as `.(+formal|--casual)`.

## Epsilon: `_`

`_` produces no output.

```text
S ::= hello _ world;
```

This is mainly useful inside optional and recursive productions.

`_` is not the underscore character in the output. It means the absence of output.

```text
S ::= ball | _;
```

This grammar produces either `ball` or nothing.

That is why optional groups can be understood as a compact epsilon-based choice.

## Concatenation: `^`

`^` removes the space that would normally be inserted between adjacent output tokens.

```text
S ::= hello ^ "!";
```

This yields `hello!` instead of `hello !`.

You can place `^` anywhere in a sequence where you want to suppress spacing.

```text
S ::= "(" ^ (apple | orange) ^ ")";
```

That yields `(apple)` or `(orange)`.

The operator can be prefixed, suffixed, or infixed relative to surrounding atoms. Repeated carets do not keep removing more than one space; effectively they collapse into a single pending concat effect.

## Capitalization: `\`

`\` capitalizes the next emitted terminal output.

```text
S ::= \ hello ^ "!";
```

This yields `Hello!`.

The capitalization flag stays pending until the next real terminal text is emitted. Intermediate epsilon, concat, or another capitalization marker do not consume it.

```text
S ::= a \ ^ \ _ b;
```

This yields `aB`.

## Optional Groups: `[ ... ]`

Square brackets represent an optional subgrammar.

```text
S ::= hello [ world ];
```

The optional body can either produce its content or disappear as epsilon.

## Mobile Groups: `{ ... }`

Curly braces mark mobile groups. During preprocessing, mobile atoms may be permuted with each other inside the same sequence.

```text
S ::= the quick {fox} jumped over the lazy {dog};
```

Permutation only happens among mobile groups that belong to the same sequence.

```text
S ::= whether {is} {therefore} {he};
```

This can generate all orderings of the three mobile groups.

If mobile groups live in different nested subproductions, they do not permute across those boundaries.

## Unfold: `>`

`>X` unfolds a non-terminal or group into a subgrammar form during compilation.

```text
S ::= >Phrase;
Phrase ::= hello | world;
```

The current port rejects cyclic unfold chains such as `S ::= >S;`.

Unfolding is mainly about flattening a grouped or referenced choice into the surrounding series, which changes probability distribution without forcing you to rewrite the grammar manually.

### Unfolding Non-Terminals

```text
S ::= ugly cat | nice >Dog;
Dog ::= poodle | beagle | terrier;
```

Without unfold, the choice is between:

- `ugly cat`
- `nice Dog`

With unfold, the choice is redistributed across:

- `ugly cat`
- `nice poodle`
- `nice beagle`
- `nice terrier`

### Unfolding Groups

```text
S ::= >(walk | pass) through | look at;
```

This behaves like:

```text
S ::= walk through | pass through | look at;
```

### Unfolding Optional And Mobile Groups

Optional and mobile groups are also unfoldable.

- Unfolding an optional group expands the same body-vs-epsilon choice the group already represents.
- Unfolding a mobile group happens after permutation logic has been applied within its sequence.

That means syntax such as `>[ ... ]` and `>{ ... }` is meaningful in the current implementation.

### Unfolding Deeply Unfolded Groups

You can also unfold the result of a deep-unfolded group, for example `> >> ... <<`.

This is useful when you want recursive flattening first, then want the resulting subgrammar lifted into the surrounding series.

## Deep Unfold: `>> ... <<`

Deep-unfold recursively marks unfoldable atoms inside a group so they are flattened more aggressively than with a single `>`.

```text
S ::= look at >> the (dog | (sorian | persian) cat)
		  | a (cow | bull | Animal)
		 <<;

Animal ::= pig | (weird | ugly) chicken;
```

In the current implementation, deep-unfold walks the enclosed production recursively and turns nested groups and non-terminals into unfolded targets, unless they are explicitly locked.

This makes `>> ... <<` the concise way to say “deeply flatten this region” without writing `>` in front of every unfoldable atom.

## Lock: `<`

`<X` locks a target against unfolding.

Use this when you need the non-terminal or group to remain intact instead of being unfolded by surrounding syntax.

It is especially useful inside deep-unfolded regions where most atoms should flatten, but one specific atom should remain grouped or referenced.

```text
S ::= >> the (dog | <(sorian | persian) cat)
	| a (cow | bull | <Animal)
     <<;
```

Here the locked subgroup and locked non-terminal are preserved while the rest of the deep-unfolded region is flattened.

## Positional Generation: `,`

Commas inside the same position create positional variants.

```text
S ::= he,she is a handsome,pretty act ^ or,ress;
```

This behaves like:

```text
S ::= he is a handsome actor | she is a pretty actress;
```

All comma-separated groups in the same sequence must have the same width. The current compiler rejects heterogeneous positional groups.

This feature is useful when multiple pieces of a sentence need to vary together without introducing labels.

## Iteration: `( ... )+`

Appending `+` to a parenthesized group means “repeat this grouped production one or more times”.

```text
S ::= she is s ^ (o ^)+ pretty;
```

This can generate `so pretty`, `soo pretty`, `sooo pretty`, and so on.

The repeated body is regenerated each time. If you want repeated output to reuse the same chosen value, combine iteration with an assignment-bound symbol:

```text
S ::= (X := a | b; (X)+);
```

That gives repeated `a` or repeated `b`, instead of choosing afresh on every repetition.
